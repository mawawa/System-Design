Introduction

Lecture Notes

Software Design is the process of transforming user requirements into a suitable form, which helps the programmer in software coding and implementation

During the software design phase, the design document is produced based on the customer requirements as documented in the Software Requirements Specification (SRS) document

Hence software design aims to transform the SRS document into a design document.

The following items are designed and documented during the design phase:

  • The different modules required
  • the control relationships among the modules
  • The interfaces among the different modules
  • The Data structures among the different modules
  • The Algorithms that are required to implement the individual modules.

Software Development Terminology

Software Engineering
software engineering encompasses the entire process of designing, building and maintaining software systems.
Software Design
This focuses on specifically the planning and conceptualization of the software architecture.
Software Development
The refers to the act of writing code to implement that design and bring the software to life.
Abstraction
this is simply means to hide the details to reduce complexity and increase efficiency
Modularity
This means dividing the systems or project into smaller parts to reduce complexity of the system of project.
Architecture
This means a technique to design a structure of something
Refinement
this means to refine something to remove any impurities if present and increase the quality.
Pattern
A Pattern simply means a repeated form of design which the same shape is repeated several times to form a pattern.
Information Hiding
Information hiding means to hide the information so that it cannot be accessed by unwanted party.
Refactoring
Refactoring means reconstructing something in such a way that it does not affect the behavior of any features.

Design Objectives

The main objectives to software design are as followos
  • Correctness - A good design should be correct, that is it should implement all the functionalities of the system.
  • Efficiency - A good software design shold address the resources in terms of times and cost optimization.
  • Understandability - A good software design should be easily understandable, it should be modular, and all the modules be arranged in layers.
  • Flexibility - A good software design should have the ability to adapt and accommodate changes easily.
  • Completeness - A good software design should have all the components like data structures, modules, external interfaces , etc...
  • Maintainability - A good software design aims to create a systems that is easy to understand, modify and maintain of time.

Maintainability

A good software design aims to create a system that is easy to understand , modify, and maintain over time. This involves using modular and well structured design principles. Maintainability in software and design also enables developers to fix bugs, enhance features and adapt the software to changing requirements without excessive effort of introducing new issues.
